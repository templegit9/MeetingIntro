Three fixes, one of them to a feature that shipped yesterday.

### The expanded calendar shows the day you picked

Selecting a date showed a correct count — "2 meetings" — and then listed *today's* schedule underneath it. The summary and the list were answering different questions. The list is now the selected day's own meetings; the "next up" block appears only when the chosen day is empty, where knowing what's next instead is actually useful. Meetings that have already finished are dimmed rather than hidden, because on today's date the morning is still part of the day you're looking at.

### The update button stops naming commands that can't work

Two dead ends. It printed `brew upgrade --cask meetingintro` without the tap, which fails for anyone who hasn't tapped `templegit9/tap`. And when an update needs your Mac password — which happens when the copy in Applications isn't owned by your user account — it reported a generic failure with the real reason truncated out of view. It now says plainly that a password is needed and that running it once in Terminal fixes it for good.

If the app was installed by unzipping a release rather than through Homebrew, it now says so and points at the download, instead of suggesting a `brew` command that can never succeed for that copy.
