### New

**MeetingIntro can now check your Exchange meetings against Microsoft 365 directly.**

macOS Calendar sometimes fails to apply a change from Exchange and leaves a meeting behind after it has been cancelled on the server. There is nothing in the local copy to distinguish it from a real meeting, so the app faithfully reminds you about something that is not happening. One user was reminded about a meeting cancelled a week earlier, and auto-join opened a Zoom for it.

Turn on **Settings → Calendar → Verify against Microsoft 365** (after signing in under Microsoft Graph API). Meetings on Exchange calendars are cross-checked against the server every 5 minutes, and anything the server says is cancelled, or no longer has at all, stops firing reminders and will not auto-join.

- **Your calendar source doesn't change.** macOS Calendar still provides everything you see, including calendars that have nothing to do with Exchange. This only adds a second opinion where one is available.
- **It errs towards leaving you alone.** If Microsoft 365 can't be reached, or returns nothing, the check is skipped rather than treated as "everything is cancelled". A meeting has to fail two checks in a row before it goes quiet.
- **The diagnostic log says why.** A suppressed meeting is logged with its reason, so "why didn't I get a reminder?" has an answer.

Off by default. Note that most workplaces require an IT administrator to approve calendar access for any third-party app, so you may need to ask.

Signing in now also requests access to **calendars shared with you**, so meetings on a shared or delegated calendar can be verified too.
