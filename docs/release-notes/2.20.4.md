### New

**Use both calendar sources at the same time.** macOS Calendar and Microsoft 365 are no longer an either/or choice. Turn on both in **Settings → Calendar** and your Google and iCloud calendars come through macOS Calendar while a work Outlook calendar comes straight from Microsoft 365. A meeting that appears in both is shown once, and if one source fails the other still loads.

**Quick Add can create events in Outlook, and invite people.** Pick where new events go with **Create new events in**, then type an email address into New Event and that person is invited. macOS Calendar gives apps no way to add attendees, so when events are being created there the preview says in orange that the invitees will not be invited. Only real addresses are used. Typing "meet John tomorrow" invites nobody, because inviting the wrong person cannot be taken back.

**RSVP now follows the meeting, not the app.** Accept and Decline are offered per meeting based on the source it actually came from, so a merged list no longer hides the buttons on a meeting that supports them.

### Fixes

**Microsoft 365 was showing zero meetings.** Two separate faults, both fixed:

- The app only ever read your **default** Outlook calendar. Calendars you ticked in Settings were saved and then ignored, so a work account whose meetings live anywhere else returned nothing at all, with no error to explain it. Every ticked calendar is now read individually, one unreadable calendar no longer takes the whole account down with it, and the default calendar remains the fallback.
- Every Microsoft 365 event was being discarded while it was being read. Microsoft sends the time as wall clock with the timezone in a separate field, which the date reader rejected, so meetings arrived and were thrown away silently. Times from Microsoft 365 now read correctly.

**Ticked calendars from a previous account are removed automatically.** Calendar identifiers belong to one account, so signing in as someone else left behind ticks that could not be unticked from the new account's list. Those are now dropped as soon as Microsoft says the calendar is gone, and the whole selection is cleared when the signed in account changes.

**Settings now tells you which Microsoft account is connected.** It said "Signed In" and then "Checking account…" forever — the lookup was attached to an invisible element that macOS never draws, so it never ran. It now shows the name and address of the signed-in account, which matters when a work and a personal account are both in play. If the lookup fails, it says so instead of pretending to still be checking.

**Switching to the Microsoft 365 tab no longer launches a sign in.** A background refresh could trigger the browser sign in on its own. Sign in now happens only when you press Sign In.

**The diagnostic log explains an empty calendar.** A source skipped for want of a sign in, a source that is connected but returns nothing, a calendar that could not be read, and a fetch that returns events none of which could be read are each written to the log now. Every one of those used to look identical from the outside: nothing.
