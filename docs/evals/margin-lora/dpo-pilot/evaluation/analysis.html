These are raw model outputs. No calendar, file, or memory action was executed. Native safeguards are separately tested; a blocked wrong proposal is not successful task completion.

Assessment

DPO does not improve the tested service overall: 300/381 attempted requests passed (78.7%). On the identical 20-case workstation subset, DPO passes 36/60 attempts versus base 42/60. It improves one quoted-memory case but regresses attendee handling and causes parser errors on two previously working batch cases.

The 15 critical-labelled failures include nine inappropriate memory writes, three wrong tool routes for emptying Trash, and three unnecessary refusals to describe capabilities. This label does not mean 15 destructive actions occurred: no tools executed. Date moves also lose original dates or choose the wrong destination.

33 requests across 11 distinct fixtures failed Ollama native tool-call parsing. They are recorded as runtime errors, excluded from gradable-output accuracy, and included as unsuccessful attempts above. The first error was separately reproduced and its body retained. This prevents an inflated accuracy claim based only on responses that survived parsing.

Next engineering work

Keep this adapter experimental. First capture raw generation for the failing native-format cases to distinguish malformed model output from parser incompatibility; do not patch the evaluator to accept invalid calls. Then improve training coverage for original-date retention, memory provenance and temporary instructions, with new held-out variations. Keep execution safeguards independently tested. Another training run should follow a diagnosed failure mechanism, not simply more epochs.
