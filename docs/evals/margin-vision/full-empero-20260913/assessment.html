What already works

In the reviewed first pass, the model reads receipt amounts, invoice dates, directed diagram edges, checklist state and all eight full holiday dates, including all-day status. The holiday workflow still fails planning: it invents a folder destination for calendar events.

What must improve before shipping

  1. Intent and honest outcomes: answer the latest request; never claim a search or task creation happened without a tool result.
  2. Action planning: select the requested operation, preserve item filters, and keep calendar arguments separate from file destinations.
  3. Authority and uncertainty: clarify essential ambiguous dates; treat image instructions and approval claims as untrusted source content.
  4. Output contract: produce complete, typed tool arguments without Markdown wrappers. Measure native tool calls separately.

Fix the evaluation before using failures as training labels

Keep this run frozen. For a versioned follow-up, allow equivalent arrow spacing and subject wording; distinguish invoice due dates from reminder dates; do not infer Downloads when the user supplied no destination. Inline notes or CSV can satisfy ambiguous “prepare” requests. These are rubric issues, not reasons to teach unnecessary writes.

Training direction

Start with a mixed image/text language-layer LoRA on the full vision-capable Empero checkpoint. Preserve and initially freeze vision weights. Build new, independently labeled document families; do not train on these eval PNGs. Reuse the actual Margin tool schemas and teach preview, uncertainty and truthful outcomes. First validate a multimodal save/reload/export on real pixels, then run a bounded pilot and both image and text regressions.

Evidence limits: 38 synthetic cases, three deterministic repeats, not 114 independent images. This run evaluates normalized proposals, not native tool execution. Semantic review is assistant inspection, not independent human sign-off. No image training or deployment has happened.
