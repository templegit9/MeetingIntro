Margin vision architecture review

Reviewed September 12, 2026. Recommendation: evaluate the full Empero 4B vision checkpoint before training or choosing a two-model architecture. Keep Pilot 1 as the text baseline during comparison.

Qwen 3.8 naming and actual vision support

The 4B and 9B packages reviewed here are Empero distillations built on Qwen3.5, not official Qwen-team small 3.8 releases. The official Qwen release material reviewed identifies larger 3.8 checkpoints; I did not find official Qwen3.8-4B or Qwen3.8-9B releases. Qwen release repository

Both Empero model cards describe text-only distillation with untested inherited vision behavior. This makes them candidates, not validated multimodal products. 4B model card, 9B model card

I inspected the actual configs and only the safetensors headers, without downloading weights. Both declare Qwen3_5ForConditionalGeneration and contain vision tensors: 297 tensors / 333,514,240 visual parameters in 4B; 333 tensors / 456,010,480 visual parameters in 9B. These are structural checks, not inference results. Exact commits and metadata are retained in package audit.

Neither publisher GGUF file listing contains a separate mmproj artifact at the inspected revision. Absence of that artifact is a packaging gap for the normal separate-projector path, not proof the original checkpoint lacks vision. Margin's installed Pilot 1 previously reported completion/tools/thinking, without vision. Its current installation cannot be assumed to accept images merely because its ancestor can.

Train a vision-language model from scratchFull architectural controlFar beyond the data/compute needed for this productNot justified

A text-only LoRA does not create a vision encoder. Prefer a checkpoint that already has one. For adaptation, initially preserve the vision stack while training the language/task path with a mixed image-and-text dataset; selectively adapt vision only if evidence shows a perception bottleneck. This is a proposed experiment, not a guaranteed recipe. TRL multimodal SFT support

Test order

1. Confirm full Empero 4B can answer pixel-dependent questions with the correct runtime and image processor. Use no-image and changed-image controls.

2. Compare against official Qwen3.5-4B on the frozen image suite.

3. Feed identical vision observations into Pilot 1 and compare full workflow accuracy and total latency with direct multimodal proposals.

4. Evaluate the two 9B variants only if the smaller candidates leave useful quality headroom.

5. Train the best suitable base only for stable, repeated failure categories; then rerun untouched holdout, existing text evals and actual native writes/undo.
